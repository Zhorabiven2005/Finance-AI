# Finance AI

Локальное приложение для учёта личных финансов с AI-помощником.
Данные хранятся только на вашем компьютере в файле SQLite; нейросеть работает
локально через Ollama — облачных сервисов и ключей API нет.

**Текущее состояние: готовы этапы 0–3F** — учёт, аналитика, локальный
помощник, финансовые инсайты, сравнение периодов, предупреждения и ручная
классификация операций.

---

## Возможности

**Учёт**
* счета (банк, наличные, другое) и остатки, которые всегда пересчитываются из операций;
* доходы и расходы с категориями, поиском, фильтрами и пагинацией;
* переводы между своими счетами — не считаются доходами и расходами;
* назначение операции, задаваемое вручную: перевод между своими счетами,
  перевод на свой внешний продукт (вклад, договор, кредитка вне приложения),
  погашение долга или кредитки — без изменения суммы, даты и описания;
* бюджеты по категориям на месяц, финансовые цели с накоплениями,
  долги с платежами и сроками, регулярные операции;
* уведомления о сроках долгов, бюджетах и регулярных операциях.

**Аналитика и выводы** (все числа считает приложение, а не модель)
* аналитика за период: доходы, расходы, динамика, категории;
* дашборд: капитал, счета, долги, бюджеты, цели, последние операции;
* **финансовые инсайты** — доходы и расходы, структура расходов, крупные и
  регулярные расходы, бюджеты, цели, надёжность данных;
* **сравнение периодов** — текущий месяц с теми же днями прошлого, прошлый
  месяц с позапрошлым, три месяца с тремя предыдущими; «расходы на жизнь»
  отдельно от погашений долгов;
* **финансовые предупреждения** — превышение бюджета, риск по темпу трат,
  крупные расходы, резкий рост категории, просроченные цели.

**Локальный AI-помощник** (Ollama, по умолчанию `qwen3.5:4b-q4_K_M`)
* чат по вашим данным с потоковыми ответами и сверкой чисел;
* расчёт плана накоплений по цели (срок или ежемесячный взнос);
* объяснение инсайтов и сравнения периодов простыми словами.

**Данные**
* резервная копия в JSON и восстановление из неё (раздел «Импорт и экспорт»);
* экспорт в CSV, импорт операций из CSV с предпросмотром.

## Запуск на Windows

Требуется Python 3.11+ и Node.js 20+. Для помощника — [Ollama](https://ollama.com)
и модель (`ollama pull qwen3.5:4b-q4_K_M`); без неё работает всё, кроме помощника.

```
setup.bat     — один раз: venv, зависимости, .env, миграции, npm install
start.bat     — каждый день: поднимает backend и frontend, открывает браузер
stop.bat      — остановить backend и frontend
```

После `start.bat`:

| | |
|---|---|
| Интерфейс | http://localhost:5173 |
| API | http://127.0.0.1:8000 |
| Документация API | http://127.0.0.1:8000/docs |

### Обновление существующей установки

Новые версии могут менять схему базы (например, Stage 3F добавил назначение
операций). После `git pull`:

1. Остановите приложение (`stop.bat`).
2. Сделайте резервную копию базы — см. ниже.
3. Примените миграции: `scripts\migrate.bat`.
4. Запустите `start.bat`.

Без миграции новая версия с существующей базой не запустится корректно.

### Резервное копирование

* **Из приложения:** «Импорт и экспорт» → резервная копия в JSON (формат
  версии 3; файлы версий 1–2 тоже восстанавливаются).
* **Файлом:** при остановленном приложении скопируйте `backend/data/finance.db`
  вместе с `finance.db-wal` и `finance.db-shm`, если они есть, в отдельную папку.

## Принципы

**Деньги — целые числа.** Сумма хранится как целое число копеек. `float`
запрещён на уровне типов: `Money.from_major(10.55, "RUB")` выбрасывает
`TypeError`. Это защищает от накопления ошибки округления.

**Расчёты — в Financial Engine.** Пакет `app/engine/` не импортирует ни
FastAPI, ни SQLAlchemy и тестируется без базы. Роутеры остаются тонкими.

**Одно правило учёта для всех экранов.** Чем операция является для
показателей — доходом, расходом на жизнь, погашением долга или переводом, —
решает одна функция (`app/engine/flows.py`). Её используют аналитика,
дашборд, бюджеты, контекст помощника, уведомления, инсайты, сравнение и
предупреждения. Неоднозначные операции не переклассифицируются автоматически —
назначение задаёт пользователь.

**AI не считает и не действует.** Модель получает только уже посчитанные
числа из read-only контекста; у неё нет инструментов, доступа к БД, файлам и
сети. Числа её ответов сверяются с данными, расхождения показываются.

**Мультивалютность заложена в модель.** Каждая сумма несёт валюту, суммы
разных валют не складываются и не конвертируются.

## Разработка

```
scripts\run_tests.bat                    тесты backend
scripts\migrate.bat                      применить миграции
scripts\migrate.bat "описание"           создать новую миграцию
scripts\alembic_check_isolated.bat       проверка схемы без доступа к рабочей БД
cd frontend && npm test                  тесты frontend
cd frontend && npm run typecheck         проверка типов
cd frontend && npm run build             production-сборка
```

Тесты backend работают на изолированной базе в памяти и не открывают
`backend/data/finance.db`.

## Ограничения

* Возврат покупки записывается как доход; отдельного типа «возврат» нет.
* Типа счёта «кредитная карта» нет. Если погашение кредитки записано как
  погашение долга, приложение не может проверить, записаны ли сами покупки, —
  об этом предупреждает сравнение периодов.
* Курсов валют нет; суммы в разных валютах показываются отдельно.
* Модель помощника на 4 млрд параметров может ошибаться в формулировках —
  числа на экранах приложения остаются первоисточником.
