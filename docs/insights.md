# Финансовые инсайты (Stage 3C)

Раздел «Финансовые инсайты» на дашборде показывает выводы, которые backend сам находит в данных. Все суммы, доли и сравнения считает backend детерминированно; локальная модель по кнопке «Объяснить» только пересказывает уже посчитанный вывод.

## API

### `GET /api/v1/insights?period=current_month|previous_month|last_3_months`

Read-only сессия (`get_readonly_db`), модель не участвует — работает и без Ollama. Период — календарные месяцы в UTC, как у бюджетов и финансового контекста; `last_3_months` — три полных месяца до текущего.

Ответ: `period`, `currencies`, `insights[]` и `unavailable[]`. Инсайт: `id`, `type`, `title`, `severity` (`warning` / `attention` / `info`), `confidence` (`high` / `medium` / `low`), `period`, `currency` (или `null`, если у строк разные валюты), `metrics[]` (`money` в minor-единицах / `percent` / `count`), `items[]`, `summary`, `limitations[]`, `link`. `unavailable[]` объясняет, почему вывода нет: `insufficient_data`, `nothing_found`, `not_applicable`.

Порядок: сначала `warning`, потом `attention`, потом `info`.

### `POST /api/v1/insights/explain`

```json
{"insight_id": "cash_flow:RUB", "period": "current_month"}
```

Инсайт пересчитывается на сервере; в модель уходят правила помощника и блок ДАННЫЕ с этим одним выводом, вопрос — фиксированная фраза приложения. Текста от клиента в запросе к модели нет. Ответ — тот же поток NDJSON, что у чата (`meta` / `delta` / `done` с `grounding` / `error`); числа ответа сверяются с блоком данных. Неизвестный `insight_id` — 404, помощник выключен — 503, Ollama недоступен — событие `error` (`server_unreachable`), сами инсайты при этом работают.

## Выводы и правила расчёта

| Тип | Что считается | Когда не показывается |
|---|---|---|
| `cash_flow` | доходы, расходы, чистый поток по каждой валюте; переводы между своими счетами — отдельной строкой, не в доходах и расходах; изменение остатка активных счетов — из движений за период (операции + переводы), не из текущего баланса; погашения долгов названы отдельно | нет операций за период |
| `spending_structure` | расходы по категориям: 5 крупнейших + «Остальные», доли `share_percent` с округлением ROUND_HALF_UP до 0,1% | нет расходов в валюте |
| `large_expenses` | порог «крупного» = max(Q3 + 3·IQR, 5 × медиана) по расходам той же валюты за полгода (перцентили — метод ближайшего ранга); большая сумма, обычная для пользователя, крупной не считается | меньше 20 расходов за полгода; или нет трат выше порога |
| `recurring_expenses` | ≥ 3 списания с одинаковыми категорией, счётом и суммой; все интервалы 26–35 дней (месяц) или 6–8 дней (неделя); отметка, если такое правило уже есть в «Регулярных» | история меньше 2 месяцев; или регулярности нет |
| `budgets` | бюджеты текущего месяца — тем же расчётом, что экран «Бюджеты»; риск превышения — линейный темп ⌈потрачено × дней в месяце / прошедших дней⌉, только после первой недели и с пометкой «оценка, а не прогноз» | бюджетов нет |
| `goals` | прогресс и план из финансового контекста (те же расчёты, что у целей и помощника) | активных целей нет |
| `data_quality` | история короче периода; ≥ 25% расходов или доходов в «Прочих»; операции с будущей датой; замечания финансового контекста | замечаний нет |

Суммы разных валют никогда не складываются: у каждого вывода одна валюта или своя валюта у каждой строки.

## Ограничения

- Возвратов как отдельного типа в модели данных нет: возврат покупки записывается доходом и увеличивает доходы, а не уменьшает расходы (это сказано в ограничениях вывода).
- Комиссии — обычные расходы своей категории.
- Регулярные платежи с меняющейся суммой не распознаются; совпадение ищется по категории, счёту и сумме, комментарии не используются.
- Комментарии к операциям в инсайты и в модель не попадают вовсе; названия категорий и счетов очищаются (`sanitize_label`) и в промпте выводятся строковыми литералами JSON.
- Сверка чисел ответа модели проверяет значения, а не смысл: модель 4B может неверно назвать показатель — числа карточки остаются первоисточником.
- Сравнение с прошлым периодом (Stage 3D) и уведомления по инсайтам (Stage 3E) не реализованы.
