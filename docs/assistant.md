# Локальный AI-помощник

Статус: **Stage 3A — фундамент backend.** Чата и потоковых ответов пока нет (Stage 3B).

## Принципы

- **Только локально.** Модель запускает [Ollama](https://ollama.com) на этом же компьютере. Адрес сервера обязан быть loopback (`127.0.0.1`, `::1`, `localhost`), иначе backend не запустится с такой настройкой. Облачные модели Ollama (`*:cloud`, записи с `remote_host`) не используются. Ключей и облачных провайдеров нет.
- **Только чтение.** Финансы помощник получает только из read-only контекста Stage 2F ([financial-context.md](financial-context.md)) — без своих SQL-запросов и без прямого доступа к SQLite. У модели нет инструментов, файлов, SQL, shell и внешних API.
- **AI не считает.** Все суммы и показатели заранее посчитаны приложением; модель получает готовые значения с валютой (`1 234,56 ₽`). Разные валюты не складываются и не конвертируются.
- **Без свободного текста.** Комментарии, описания платежей и целей, тексты уведомлений в сводку не попадают. Названия счетов, категорий, долгов и целей — недоверенные данные: в тексте сводки они выводятся как строковые литералы в кавычках.
- **Без хранения.** История диалога и промпты не сохраняются в БД и на диск.

## Установка

1. Установите Ollama для Windows с [ollama.com](https://ollama.com/download).
2. Загрузите модель:

   ```bash
   ollama pull qwen3.5:4b-q4_K_M
   ```

3. Проверьте статус: `GET http://127.0.0.1:8000/api/v1/assistant/status` → `"state": "ready"`.

Требования (замерено на i5-13420H без видеокарты, 16 ГБ RAM): около 3 ГБ памяти, пока модель загружена; ответ 15–40 с. Модель выбрана по тесту на вымышленных данных: верные числа, отказ складывать разные валюты, устойчивость к «инструкции» в названии.

## Настройки (`backend/.env`)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `ASSISTANT_ENABLED` | `true` | Выключатель помощника |
| `ASSISTANT_OLLAMA_URL` | `http://127.0.0.1:11434` | Адрес Ollama; только loopback, без пути и учётных данных |
| `ASSISTANT_MODEL` | `qwen3.5:4b-q4_K_M` | Локальная модель; облачные отклоняются |
| `ASSISTANT_STATUS_TIMEOUT_SECONDS` | `3` | Таймаут проверки статуса |
| `ASSISTANT_DIGEST_TOKEN_BUDGET` | `2500` | Размер текстовой сводки для модели (оценка токенов) |

Старые поля `AI_PROVIDER`, `AI_MODEL`, `ANTHROPIC_API_KEY` — заготовка этапа 0; помощник их не использует.

## API

### `GET /api/v1/assistant/status`

Проверяет только локальный сервер, БД не использует. Сервер считается доступным, только если `GET /api/version` и `GET /api/tags` вернули корректный JSON Ollama — открытого порта недостаточно. Системные прокси игнорируются, перенаправления не выполняются.

| `state` | Значение |
|---|---|
| `ready` | Сервер и модель доступны |
| `disabled` | `ASSISTANT_ENABLED=false`; сервер не опрашивается |
| `server_unreachable` | Ollama не запущен (подключение не устанавливается) |
| `server_timeout` | Подключение есть, но ответа нет за таймаут |
| `server_bad_response` | По адресу отвечает не Ollama (не JSON, нет версии, HTTP-ошибка, перенаправление, слишком большой ответ) |
| `model_not_found` | Модели нет — сообщение подсказывает `ollama pull …` |
| `model_not_local` | Модель облачная — не используется |

```json
{
  "enabled": true,
  "provider": "ollama",
  "state": "ready",
  "ready": true,
  "message": "Локальная модель доступна, помощник готов к работе.",
  "server": {"url": "http://127.0.0.1:11434", "available": true, "version": "0.40.8"},
  "model": {"name": "qwen3.5:4b-q4_K_M", "available": true, "local": true, "size_bytes": 3300000000, "parameter_size": "4.0B", "quantization": "Q4_K_M"},
  "checked_at": "2026-10-25T09:00:00Z"
}
```

### `GET /api/v1/assistant/context-preview?months=6&upcoming_days=30`

То, что в Stage 3B получит модель: `digest` (структура) и `text` (сводка для промпта), `estimated_tokens`, `token_budget`, `omitted_sections`. Строится из read-only контекста через `get_readonly_db`; запрос ничего не пишет в БД и не создаёт уведомлений. Модель при этом не вызывается.

Разделы текста по приоритету: общие сведения → особенности данных → показатели по валютам → бюджеты → долги → прогноз регулярных операций → цели → счета → доходы и расходы по месяцам → категории → уведомления. Если сводка не помещается в бюджет, последние разделы опускаются целиком (с пометкой), а не обрезаются посередине.

## Ограничения Stage 3A

- Чата, промптов и вызова модели нет — это Stage 3B.
- Оценка токенов приблизительная (≈ 3 символа на токен), без токенизатора модели.
- Расхождение UTC и местной даты в регулярных операциях не исправлено — оно показывается в сводке как «неоднозначная дата».
