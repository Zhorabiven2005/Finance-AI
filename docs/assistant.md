# Локальный AI-помощник

Статус: **Stage 3B — локальный чат с потоковыми ответами** (страница «Помощник»). Инсайтов и предупреждений пока нет (Stage 3C).

## Принципы

- **Только локально.** Модель запускает [Ollama](https://ollama.com) на этом же компьютере. Адрес сервера обязан быть loopback (`127.0.0.1`, `::1`, `localhost`), иначе backend не запустится с такой настройкой. Облачные модели Ollama (`*:cloud`, записи с `remote_host`) не используются. Ключей и облачных провайдеров нет.
- **Только чтение.** Финансы помощник получает только из read-only контекста Stage 2F ([financial-context.md](financial-context.md)) — без своих SQL-запросов и без прямого доступа к SQLite. У модели нет инструментов, файлов, SQL, shell и внешних API.
- **AI не считает.** Все суммы и показатели заранее посчитаны приложением; модель получает готовые значения с валютой (`1 234,56 ₽`). Разные валюты не складываются и не конвертируются.
- **Без свободного текста.** Комментарии, описания платежей и целей, тексты уведомлений в сводку не попадают. Названия счетов, категорий, долгов и целей — недоверенные данные: в тексте сводки они выводятся как строковые литералы в кавычках.
- **Без хранения.** История диалога и промпты не сохраняются в БД и на диск.

## Установка

1. Установите Ollama для Windows с [ollama.com](https://ollama.com/download).
2. Загрузите модель:

   ```bash
   ollama pull qwen3.5:4b-q4_K_M
   ```

3. Проверьте статус: `GET http://127.0.0.1:8000/api/v1/assistant/status` → `"state": "ready"`.

Требования (замерено на i5-13420H без видеокарты, 16 ГБ RAM): около 3 ГБ памяти, пока модель загружена; ответ 15–40 с. Модель выбрана по тесту на вымышленных данных: верные числа, отказ складывать разные валюты, устойчивость к «инструкции» в названии.

## API

### `GET /api/v1/assistant/status`

Проверяет только локальный сервер, БД не использует. Сервер считается доступным, только если `GET /api/version` и `GET /api/tags` вернули корректный JSON Ollama — открытого порта недостаточно. Системные прокси игнорируются, перенаправления не выполняются.

| `state` | Значение |
|---|---|
| `ready` | Сервер и модель доступны |
| `disabled` | `ASSISTANT_ENABLED=false`; сервер не опрашивается |
| `server_unreachable` | Ollama не запущен (подключение не устанавливается) |
| `server_timeout` | Подключение есть, но ответа нет за таймаут |
| `server_bad_response` | По адресу отвечает не Ollama (не JSON, нет версии, HTTP-ошибка, перенаправление, слишком большой ответ) |
| `model_not_found` | Модели нет — сообщение подсказывает `ollama pull …` |
| `model_not_local` | Модель облачная — не используется |

```json
{
  "enabled": true,
  "provider": "ollama",
  "state": "ready",
  "ready": true,
  "message": "Локальная модель доступна, помощник готов к работе.",
  "server": {"url": "http://127.0.0.1:11434", "available": true, "version": "0.40.8"},
  "model": {"name": "qwen3.5:4b-q4_K_M", "available": true, "local": true, "size_bytes": 3300000000, "parameter_size": "4.0B", "quantization": "Q4_K_M"},
  "checked_at": "2026-10-25T09:00:00Z"
}
```

### `GET /api/v1/assistant/context-preview?months=6&upcoming_days=30`

То, что получает модель в чате: `digest` (структура) и `text` (сводка для промпта), `estimated_tokens`, `token_budget`, `omitted_sections`. Строится из read-only контекста через `get_readonly_db`; запрос ничего не пишет в БД и не создаёт уведомлений. Модель при этом не вызывается.

Разделы текста по приоритету: общие сведения → особенности данных → показатели по валютам → бюджеты → долги → прогноз регулярных операций → цели → счета → доходы и расходы по месяцам → категории → уведомления. Если сводка не помещается в бюджет, последние разделы опускаются целиком (с пометкой), а не обрезаются посередине.

### `POST /api/v1/assistant/chat`

```json
{"messages": [{"role": "user", "content": "Привет"}, {"role": "assistant", "content": "Здравствуйте!"}, {"role": "user", "content": "Что с бюджетами?"}]}
```

- Роли только `user` и `assistant`, последняя — вопрос пользователя; роль `system` и лишние поля отклоняются (422). Слишком длинный вопрос — 422; старые реплики сверх лимита отбрасываются. `ASSISTANT_ENABLED=false` — 503.
- Запрос к модели: одно системное сообщение (неизменяемые правила + блок `<<<ДАННЫЕ … ДАННЫЕ>>>` со сводкой), затем реплики. Текст пользователя в правила не попадает; ограничители блока внутри данных нейтрализуются. У модели нет инструментов (`tools` не передаётся), задачи — только пересказ данных.
- Ответ — поток NDJSON (`application/x-ndjson`), по событию на строку:

| Событие | Содержимое |
|---|---|
| `{"type": "meta", ...}` | модель, время контекста, размер сводки (`digest_tokens`), опущенные разделы, `goal_calculation` (расчёт по цели в минорных единицах или `null`) |
| `{"type": "delta", "text": "..."}` | очередной кусок ответа |
| `{"type": "done", ...}` | `finish_reason` (`stop` / `length` / `output_limit`), `truncated`, `grounding` (`checked`, `unverified`), `usage` |
| `{"type": "error", "code", "message"}` | `busy`, `server_unreachable`, `server_timeout`, `server_bad_response`, `model_not_found`, `generation_timeout`, `stream_interrupted`, `generation_error`, `internal_error`; текст без технических подробностей |

**Рассуждения модели (thinking)** не доходят до пользователя: в запросе `think: false` (проверено на `qwen3.5:4b-q4_K_M` и Ollama 0.40.8: поле `message.thinking` при этом не приходит); поле `thinking`, если появится, не пересылается; теги `<think>…</think>` в тексте вырезаются, даже если разорваны между кусками. Frontend показывает только события `delta`.

**Отмена.** Кнопка «Остановить» прерывает fetch; backend сразу закрывает соединение с Ollama — генерация прекращается. Одновременно идёт одна генерация (`busy` для второй).

**Сверка чисел.** Модель не считает деньги. После ответа backend сравнивает все числа ответа с числами сводки и вопросов пользователя (по значению: «36 000 рублей» = «36 000,00 ₽»). Несовпавшие показываются в интерфейсе: «Не удалось сверить с данными приложения: …».

**Хранение.** История диалога живёт только в памяти приложения (zustand-хранилище `features/assistant/chatStore.ts`): не сохраняется в БД, файлы, логи, localStorage; переживает переходы между разделами и исчезает при обновлении страницы или закрытии приложения.

### Вопросы о целях и накоплениях

Срок или взнос для цели обычно называет сам пользователь («за 6 месяцев», «по 20 000 в месяц»), поэтому такой расчёт не может лежать в сводке заранее. Его делает backend (`app/assistant/goal_planner.py` + формулы `app/engine/goals.py`) для каждого вопроса о цели и кладёт первым разделом в блок данных — «Расчёт по цели». Модель только пересказывает его (правило 10 промпта); числа ответа сверяются в том числе с этим разделом.

- **Когда считается:** в последней реплике есть слова о цели/накоплениях или название цели; либо в ней есть срок или взнос, а предыдущие реплики были о цели (ответ на уточняющий вопрос).
- **Что понимается:** срок — «за 6 месяцев», «через три года», «за полгода», «за 2 года и 3 месяца», «за 10 недель», «к 01.06.2027», «к марту 2027», «к концу года»; взнос — «по 20 000 в месяц», «15 тыс в месяц», «по 5к в неделю», «ежемесячно по 12 500,50 ₽». Число лет вроде «в 2026 году» и сумма цели («накопить 300 000») взносом не считаются.
- **Цель:** по названию в вопросе (в любой форме слова); если цель одна — она; если несколько и не ясно какая — уточняющий вопрос «Для какой цели посчитать…». Архивные цели не рассматриваются.
- **Расчёт:** нужный взнос = ⌈остаток / число взносов⌉ (вверх до копейки, последний взнос меньше); число взносов при заданном взносе = ⌈остаток / взнос⌉; срок в месяцах — по календарным месяцам, как у плана цели в контексте. Если указаны и срок, и взнос — «реально ли»: хватит ли взноса, сколько накопится к сроку и сколько не хватит. Без срока в вопросе берётся срок самой цели.
- **Без выдумок:** нет ни срока, ни взноса — один уточняющий вопрос, без придуманных значений. Цель достигнута — так и сказано. Взнос ≤ 0 — срок не считается. Взнос в другой валюте — не пересчитывается (курсов нет). Прошедшая дата — просьба назвать новую. Больше 100 лет — «план нереалистичен».
- **Допущения** (передаются модели): равные взносы, без процентов и инфляции, остатки на счетах в цель не входят, прошлый доход не гарантирует будущий.

## Интерфейс

Страница «Помощник» (`/assistant`): статус модели с инструкцией, если Ollama не запущен или модели нет; быстрые вопросы; поле вопроса со счётчиком длины (Enter — отправить, Shift+Enter — новая строка); ответ появляется постепенно; «Остановить» во время генерации; под ответом — результат сверки чисел, пометка об обрезке; «Повторить вопрос» после ошибки; «Очистить диалог» с подтверждением.

Переход в другой раздел во время ответа генерацию не прерывает: ответ дописывается в фоне, при возвращении виден текущий статус. «Готово» ставится только по событию `done`; обрыв потока — ошибка. Пока идёт ответ, второй вопрос не отправляется (защита и в хранилище, и на backend — `busy`). Недописанный вопрос тоже сохраняется при переходах.

## Ограничения

- Модель на процессоре: первый ответ 15–40 с (загрузка модели и разбор сводки), дальше быстрее.
- Сверка чисел проверяет значения, но не смысл: верное число в неверном контексте не будет помечено.
- Модель 4B может ошибаться в формулировках; ответы — пересказ, а не финансовая консультация.
- Оценка токенов приблизительная (≈ 3 символа на токен), без токенизатора модели.
- Расхождение UTC и местной даты в регулярных операциях не исправлено — оно показывается в сводке как «неоднозначная дата».
